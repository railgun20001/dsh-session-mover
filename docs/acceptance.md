# 真机验收矩阵

本文件是 `dsh-session-mover` 发布前的真机验收清单。单元测试只覆盖纯逻辑
（账本、索引、护栏、日志、还原），**下面这些必须在一台真实 DSH 上逐条走一遍**，
因为它们的失败模式大多来自官方实现里没有文档化的行为（剪枝、attach 校验、工作目录自愈）。

## 环境记录

| 项 | 值 |
|---|---|
| DSH 版本 | 待填（`dsh --version` / 桌面版「关于」） |
| profile | 待填（`web` / `desktop`） |
| Node | 待填（`node -v`） |
| 插件版本 | 0.1.0 |
| 操作系统 | Windows 11（主目标平台）；Linux 仅需覆盖纯逻辑路径 |

## 用例

图例：`⏳` 待执行、`✅` 通过、`❌` 失败（失败时把日志片段贴在本节下方）。

### A. 基本移动

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| A1 | 拖动到另一个项目标题 | 两个项目各有 1 个会话，把 A 的拖到 B 标题 | 会话立刻出现在 B 顶部；A 不再列出；提示条带「还原」 |
| A2 | 拖到目标项目的某个会话行 | 拖到 B 中第二个会话上 | 插到该会话之前 |
| A3 | 同组内拖动 | 在同项目内上下拖 | 走官方手动排序，插件不干预 |
| A4 | 拖回原项目 | 把 A2 的结果拖回 A | 归属回到 A；提示条可再次还原 |
| A5 | 长列表边缘滚动 | 30+ 会话，拖到侧栏上下边缘 | 列表自动滚动，越靠边越快 |

### B. 重启与跨会话持久化

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| B1 | 移动后重启 DSH | 移动 → 完全退出 → 启动 | 会话仍在目标项目；日志出现「已挂载…写前护栏=patched」 |
| B2 | 启动自检 | 移动 1 个会话后重启 | 日志出现「自检：受管会话 1 个（目标目录缺失 0…）」 |
| B3 | 重启后打开移动过的会话 | 点击该会话发一条消息 | 工具在目标项目目录执行（`pwd`/`cwd` 验证） |

### C. 写路径护栏（重点）

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| C1 | 改名同项目 | 移动会话到 B → 重命名 B | 改名为成功，移动过的会话仍在 B（没被剪枝） |
| C2 | 排序/置顶 | 在 B 里拖动另一个会话排序 | 受管会话保持在场 |
| C3 | 在 B 新建会话 | 在 B 里新建一个对话 | 受管会话保持在场，新会话正常出现 |
| C4 | 删除同项目其他会话 | 删除 B 里另一个会话 | 受管会话保持在场 |
| C5 | 归档/取消归档受管会话 | 归档再取消归档 | 归属不变，仍受管 |

### D. 分叉（attach 接管）

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| D1 | 从**未移动**会话分叉 | 分叉普通会话 | 官方行为不变：子会话进原项目 |
| D2 | 从**移动过**的会话分叉 | 移动 A→B，再分叉该会话 | **不出现** `session/workspace-attach-failed`；子会话进 B；日志出现「按归属账本接管」 |
| D3 | 分叉会话再分叉 | 对 D2 的子会话再分叉 | 仍进 B，链路不断 |
| D4 | 父会话未分组时分叉 | 把父会话还原到未分组后再分叉 | 子会话进未分组，不报错 |

> D2 是本次护栏的主要目标：官方 `forkWorkspace()` 按账本选 B，而 `attachSession()`
> 要求 `header.cwd === B`，移动过的会话 header 仍是 A，必然校验失败。若 D2 仍报错，
> 说明实体的 `attachSession` 不是从原型可达的那一个，需回到 `lib/guards.js` 排查。

### E. 还原与卸载

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| E1 | 还原按钮 | 移动后点「还原」 | 回到原项目；`managed()` 里该条消失 |
| E2 | 一键还原 | 移动 2 个会话后执行 `__DSH_SESSION_MOVER__.restoreAll()` | 两个都回原项目；提示「已还原 2 个」 |
| E3 | 原项目已删 | 移动后删掉原项目（或改文件夹名）→ 再还原 | 会话回到「未分组」，不报错 |
| E4 | 卸载插件 | 先 `restoreAll()` 再卸载 | 卸载后归属与原来一致 |
| E5 | 直接卸载（不还原） | 移动后直接卸载 | 会话落到「未分组」；重装插件后恢复（用于确认文档描述属实） |

### F. 目录异常

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| F1 | 目标项目目录被改名 | 移动后把 B 的文件夹改名 | 启动自检 warn「目标目录不存在」；文件树报错但不崩 |
| F2 | 原项目目录被删 | 移动后删掉 A 的文件夹 | 自检 warn「原目录已被删除」；会话文件随之消失（确认文档警告） |
| F3 | 目标目录在可移动磁盘上 | 移动到 U 盘上的项目后拔盘 | 工作目录不会被静默拉回旧项目以外的目录；自检告警 |

### G. 双 profile 与多窗口

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| G1 | desktop 与 web profile | 在 desktop 移动会话，打开 web profile | web 里该会话仍在原项目（两个 profile 账本独立，符合预期） |
| G2 | 同 profile 多标签页 | 打开两个浏览器标签 | 两个标签都显示新归属；还原后都回原项目 |

### H. 读取侧投影

| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| H1 | 文件树根目录 | 打开移动过的会话的文件树 | 列的是新项目目录的内容 |
| H2 | 「打开文件夹」 | 点会话头部的打开文件夹 | 打开新项目目录 |
| H3 | 相对路径引用 | 对话里 `@文件` 或相对路径 | 按新目录解析；旧目录绝对路径提示越界（符合已知边界） |
| H4 | 移动后立即生效 | 不刷新页面直接看文件树 | 已指向新目录（`refreshOwnership()` 重放） |
